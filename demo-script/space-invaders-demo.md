# Space Invaders Demo Script (20 mins)

## Overview
Live demonstration of Cursor's key features by building a simple Space Invaders game. This demo showcases the workflow attendees will use to build their Figma plugin.

---

## Demo Flow

### 1. New Project Setup (2 mins)
**Actions:**
- Open Cursor
- Create new folder: `space-invaders`
- Open folder in Cursor
- Show empty file explorer

**Talking Points:**
- "We start with an empty folder - that's all we need"
- "Notice the clean interface - no intimidating code yet"
- "This is where our project files will live"

---

### 2. Plan Mode - Describe the Game (3 mins)
**Actions:**
- Press `Cmd/Ctrl + L` to open Agent Chat
- Switch to "Plan" mode (toggle in chat)
- Type: "Build a Space Invaders game with basic web tech"
- Review the generated plan
- Click "Yes" to build

**Talking Points:**
- "Plan mode helps us think before building"
- "Notice it suggests files: HTML, CSS, JavaScript"
- "HTML = structure, CSS = styling, JavaScript = functionality"
- "Let's see what it generates..."

**What to Highlight:**
- The plan shows what files will be created
- It lists features and to-do items
- This is the "thinking" phase before coding

---

### 3. Preview and Test (2 mins)
**Actions:**
- Wait for code generation to complete
- Click browser preview icon
- Test the game (move, shoot)
- Show it actually works!

**Talking Points:**
- "Look - we have a working game in seconds!"
- "No manual coding required"
- "The AI understood our request and built it"

---

### 4. Iterate - Fix an Issue (5 mins)
**Actions:**
- Notice the page scrolls when using arrow keys
- Start new chat (or continue current)
- Type: "When using arrow keys, the page scrolls. Fix this."
- Review the code changes (diff view)
- Accept changes
- Test again - issue fixed!

**Talking Points:**
- "This is the iterative process - build, test, improve"
- "We describe the problem in plain English"
- "AI makes the code changes"
- "Notice the diff view - shows exactly what changed"

**Key Concept:**
- Natural language → Code changes
- You don't need to know the exact code
- Just describe what you want

---

### 5. Git Checkpoint (2 mins)
**Actions:**
- Switch to Git view (left sidebar)
- Click "Initialize Repository"
- Write commit message: "Initial game"
- Click "Commit"

**Talking Points:**
- "Git is like saving checkpoints"
- "If we make a mistake, we can go back"
- "Version control is important even for small projects"

---

### 6. Ask Mode - Learn How It Works (3 mins)
**Actions:**
- Switch to "Ask" mode in chat
- Type: "Explain how this game works like I'm a beginner"
- Show the explanation
- Optionally ask: "What does requestAnimationFrame do?"

**Talking Points:**
- "Ask mode is like having a coding tutor"
- "Don't just accept code - understand it"
- "AI can explain concepts at your level"
- "This is how you learn while building"

**Key Concept:**
- Use AI to learn, not just generate
- Ask questions about the code
- Build understanding progressively

---

### 7. Rules File (2 mins)
**Actions:**
- Start new chat
- Type: "Create a rule to always use retro green styling"
- Show the rule being created
- Explain it persists across chats

**Talking Points:**
- "Rules are like preferences for the AI"
- "They persist across all conversations"
- "Useful for consistent styling or patterns"
- "Saves you from repeating instructions"

---

### 8. Context Window Reminder (1 min)
**Actions:**
- Point to context gauge
- Show it's at ~10-15% used
- Explain why this matters

**Talking Points:**
- "This gauge shows AI's working memory"
- "Keep it under 80% for best results"
- "Start new chats for new features"
- "Be intentional about context"

---

## Key Takeaways to Emphasize

1. **Plan first, then build** - Use Plan mode
2. **Iterate in small steps** - Build, test, improve
3. **New chat = fresh memory** - Be intentional
4. **Ask questions** - Use AI to learn, not just generate
5. **Use rules** - Encode preferences for consistency

---

## Common Questions & Answers

**Q: Do I need to know how to code?**
A: No! You need to know how to describe what you want. The AI handles the code.

**Q: What if the AI makes a mistake?**
A: That's normal! Describe the issue and ask it to fix it. Iteration is part of the process.

**Q: Can I use this for real projects?**
A: Yes! Cursor is used by professional developers daily. Start small and build up.

**Q: How do I know what to ask?**
A: Start with what you want to achieve, not how to code it. "Make the ship move faster" not "Change the velocity variable."
